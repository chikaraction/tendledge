# バックログ(マイルストーン積み残し・保留項目)

特定のマイルストーンに紐づけずに温めておく改善候補を管理する。
マイルストーンの計画時にここへ項目を移す/ここから拾うことで、
各 `docs/milestone-N-plan.md` のスコープを純粋に保つ。
着手するときは roadmap のマイルストーンに昇格させるか、単発の feature ブランチで対応し、
完了したら項目を消す(経緯はコミット履歴に残る)。

## 検索パネル UI の全面自作(出自: M13 #11・需要確認待ち)

- M13 では CodeMirror 標準検索パネルを「日本語化(phrases)+ Slate スタイル」で
  整えるに留めた。レイアウトごと変えたくなったら `search({ createPanel })` で
  パネル UI を自作し、検索・置換エンジンは引き続き @codemirror/search を流用する。

## 図の拡大表示(出自: M11 Mermaid・需要確認待ち)

- ガントチャート等の横長の図が本文カラム(46rem)に縮んで見にくい。
- 設定いじりの小手先対応ではなく、クリックで拡大(ライトボックス)や
  図だけ全幅表示のような機能として設計する。
- 当座はプレビューのフォントサイズ連動拡大(`--diagram-scale`)で代用できる。
- M12(Kroki 経由の PlantUML / Draw.io)で図の種類が増えると需要も増える見込み。
  対応するならリモート図(`<img>`)とローカル図(inline SVG)の両方に効く設計にする。

## ドロップダウン開閉配線の共通化(出自: M17 #3・3例目が現れたら)

- `core/menu.ts` の状態機械の実質的な価値は「複数メニュー間のホバー切り替え」。
  タブ一覧は単独ドロップダウンなので、共有できる core ロジックは boolean 1個分しかなく、
  状態機械の再利用は形だけの統一になる。
- 実際の重複は ui 層の「外側クリック + Escape で閉じる」配線だが、両者は方式が異なる
  (menubar: 常設の window `click` リスナー + 各所の `stopPropagation` 前提 /
  tabs: 開いている間だけの `pointerdown` capture)。統一するには menubar 側の
  stopPropagation 連鎖を触ることになり、ユーザー可視の利得ゼロに対して回帰リスクが見合わない。
- 将来ドロップダウンが 3 例目として増えた時点で、共通ヘルパー(`ui/dropdown.ts` 案)を
  抽出するのが妥当。
