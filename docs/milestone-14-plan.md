## 1. ウィンドウクローズ時の未保存ガード

**現状**: Ctrl+W(`closeTab`)は `window.confirm` で dirty タブの破棄を確認しているが、
ウィンドウの✕ボタンには何のフックもない(`onCloseRequested` / `beforeunload` はコード
ベースに存在しない)。✕クリックで未保存の変更が無言で失われる。

**設計**:

- Tauri 実機: `@tauri-apps/api/window` の `getCurrentWindow().onCloseRequested(handler)`。
  `store.list().some((d) => store.isDirty(d.id))` が true なら `window.confirm` で確認し、
  キャンセルなら `event.preventDefault()`。
- ブラウザプレビュー(Tauri なし): `beforeunload` で同じ dirty 判定を行い、
  dirty なら `event.preventDefault()`(Chrome 系は独自メッセージを出さず既定文言になるが、
  確認ダイアログ自体は出る)。`isTauri()`(`@tauri-apps/api/core`、`ui/kroki.ts` に使用例あり)
  で分岐し、Tauri 実機では `beforeunload` を登録しない(`onCloseRequested` と二重に
  確認ダイアログが出るのを避ける)。
- dirty 判定はロジックとして独立させる価値があるため `core/documents.ts` の
  `DocumentStore` に `hasDirty(): boolean` を追加する(テストファースト)。
  `closeTab` の既存ロジックはそのままだが、可読性のため同メソッドを使うよう揃える。

**パーミッション確認(実物確認・推測しない)**:

`onCloseRequested` は内部で `listen("tauri://close-requested", ...)` を使い、
`preventDefault` しなかった場合は `this.destroy()`(`invoke("plugin:window|destroy")`)を呼ぶ
(`node_modules/@tauri-apps/api/window.js` で実装を確認)。
インストール済み `tauri-2.11.5` crate の `permissions/window/autogenerated/reference.md` を
確認したところ、`core:window:default` の一覧に `allow-destroy` は**含まれない**
(問い合わせ系コマンドのみが default)。よって `core:default` だけでは不足しており、
`src-tauri/capabilities/default.json` に `core:window:allow-destroy` を追加する必要がある。
`listen`/`unlisten` は `core:event:default`(`core:default` に含まれる)でカバー済みのため
追加不要。

## 2. `walkDir` の堅牢化(main.ts)

**現状**: `walkDir` は `readDir` を再帰呼び出しし、1箇所でも reject すると
`Promise.all` ごと失敗する。呼び出し元の `refreshVault` にも `doOpenFolder` にも
try/catch がなく、再読み込みボタンのクリックハンドラも `void refreshVault()` で
エラーを握りつぶす(未処理の Promise 拒否 → 無言失敗)。深さ上限もないため、
Windows のジャンクション/シンボリックリンクが自己参照する構成だと無限再帰しうる。

**設計**:

- `walkDir` に `depth` 引数を追加し、`core/vault-tree.ts` に追加する
  `MAX_VAULT_DEPTH`(20)と純粋関数 `exceedsMaxVaultDepth(depth)` で上限判定する
  (テストファースト。fs 呼び出し自体は main.ts に残すが、上限の判定だけ core に切り出す)。
  上限を超えたフォルダは中身を潜らずに空配列を返す。
- 各サブフォルダの `readDir` 呼び出しを try/catch し、失敗(アクセス拒否等)したフォルダは
  ログに残しつつスキップし、残りのエントリで処理を継続する。
- `refreshVault` を try/catch し、失敗時は `window.alert` でユーザーに通知する
  (`openFileInTab` のエラー表示と同じパターン)。`doOpenFolder` と
  再読み込みボタンのクリックハンドラの両方から、この通知込みの `refreshVault` を呼ぶので
  二重に alert は出ない。

## 3. タブ切替スクロール復元の競合修正

**現状の問題**(レビューで確認済み):

- `switchEditorTo` は `preview.render(...).then(() => { scrollTop 復元; resumeScrollSync(); })`
  という形で、`render()` の Promise 解決(mermaid/Kroki の非同期完了込み)を待ってから
  scrollTop を復元している。一方で `innerHTML` の差し替え自体は `render()` 内で同期実行される。
- 素早い連続タブ切替 A→B→C で、B の `.then()` が C への切替後に解決すると
  (B に図があり C にない場合など)、C 表示中に B の scrollTop が適用されてしまう。
- `ui/scroll-sync.ts` の `suspend()` は単純な boolean フラグなので、B の `resume` が
  C の切替中に同期を誤って再開してしまう。

**設計**:

- `switchEditorTo` で `preview.render()` 呼び出し**直後**(同期)に
  `preview.paneEl.scrollTop` を復元する。`innerHTML` 差し替えは同期なので、
  この時点で見出しアンカーは新タブのものになっており正しい位置に飛べる。
- 図の非同期完了後にアンカーが再構築される(`decorateDiagrams` が
  `rebuildHeadingAnchors` を呼び直す)ケースのため、`.then()` 側は
  「もう一度 scrollTop を当てる」だけの後始末に格下げし、世代カウンタで
  古い切替の結果を無視する。
- `ui/scroll-sync.ts` の `suspend()` を **カウント方式**に変更する。
  `suspend()` を呼ぶたびにカウンタを +1 し、返す resume 関数はそれぞれ
  自分の呼び出し分だけ -1 する。カウンタが 0 に戻るまで実際の再開(=同期を
  ブロックする `suspended` フラグの解除)はしない。これにより A→B→C の連続切替で
  「最後に suspend したものが確定するまで resume されない」ことが保証される。
  既存コメント(rAF + setTimeout フォールバックの経緯)は変更しない。
- `switchEditorTo` 側は、世代カウンタ(`main.ts` に `let scrollRestoreGeneration = 0`)を
  持ち、`.then()` 内で「自分が最新の切替か」を確認してからのみ scrollTop 再適用と
  `resumeScrollSync()` を呼ぶ。古い世代の resume はスキップする
  (suspend 自体はカウント方式で二重に安全だが、無駄な再適用も避ける)。

## 4. `ui/shortcuts.ts` の修飾キー判定

**現状**: `if (!e.ctrlKey)` で早期リターンした後、各キー分岐は Shift/Alt の状態を
見ずに発火する。特に `key === "f"` は Ctrl+Shift+F でも発火し、AltGr+F
(Windows では `ctrlKey: true, altKey: true` として届く。欧州系レイアウトで
文字入力に使われるキー)でも Ctrl+F 相当の動作をしてしまい文字入力を潰す。

**設計**: 影響を最小化するため、keydown ハンドラ冒頭の早期リターン条件を
`if (!e.ctrlKey || e.altKey)` に変える。これにより AltGr 併押下(=Alt 併押下)の
ケース全体で以降の分岐に入らなくなり、Ctrl+F だけでなく Ctrl+N/O/S/P/W 等も
一括で AltGr 誤爆から守れる。Shift は個別分岐(`key === "f"` 等)ですでに
使っている(`s`+Shift → 名前を付けて保存、`v`+Shift → プレビュー切替)ため、
`f` の分岐にだけ「Shift 押下なら発火しない」条件を追加する
(`key === "f" && !e.shiftKey`)。chord(`Ctrl+K V`)状態のリセット挙動は
`resetChord()` 呼び出し位置を変えないため影響なし。

## 5. ウィンドウ最小サイズ + divider の分母ガード

- `src-tauri/tauri.conf.json` の `app.windows[0]` に `minWidth: 480`, `minHeight: 320` を
  追加する(既定 800×600 より小さく、Slate レイアウトが破綻しない値。実機確認が必要)。
- `ui/divider.ts` の `(editorPaneWidth - gutterWidth) / (contentWidth - gutterWidth)` は
  分母(`contentWidth - gutterWidth`)が 0 以下・極小になると `ratio` が `NaN`/`Infinity`
  になり `--editor-ratio` に不正値が入る。分母が閾値(50px)未満なら `onMove` を
  そのまま return して `--editor-ratio` を更新しないガードを追加する。

## 実機確認で発覚した問題と対処(2026-07-11 追記)

**症状**: 実機(`npm run tauri dev`)で、(1) dirty タブの✕ボタンで確認ダイアログが
出ずにタブが閉じる、(2) ウィンドウの✕ボタンでも確認が出ずにアプリが終了する。

**原因**: Tauri 実機(WebView2/wry)では `window.confirm` / `window.alert` が
ダイアログを表示せず**サイレントに素通りする**(wry が JS ネイティブダイアログ未実装)。
ブラウザプレビューでは普通に動くため、実機確認まで発覚しなかった。
`closeTab` の confirm は M14 以前からの潜在バグ、`onCloseRequested` 内の confirm は
#1 で追加した分、ほかに `openFileInTab` / `refreshVault` 失敗時の `window.alert` も
同罪(計4箇所)。

**対処**: `src/ui/dialogs.ts` を新設し、`confirmDialog` / `alertDialog` に集約した。
`isTauri()` で分岐し、実機は `@tauri-apps/plugin-dialog` の `confirm` / `message`
(OS ネイティブダイアログ)、ブラウザプレビューは従来の `window.confirm` /
`window.alert` にフォールバックする。`onCloseRequested` はハンドラを async にして
`await confirmDialog(...)` → キャンセルなら `preventDefault()`(onCloseRequested は
async ハンドラの解決を待ってから destroy を判断するため、この形が公式ドキュメントの
推奨パターン)。

**パーミッション**: `dialog:default` に含まれるのは `allow-message` / `allow-save` /
`allow-open` のみで **`allow-confirm` は含まれない**(インストール済み
`tauri-plugin-dialog-2.7.1` crate の `permissions/default.toml` と
`gen/schemas/desktop-schema.json` で確認)。`capabilities/default.json` に
`dialog:allow-confirm` を追加した。`message` は default に含まれるため追加不要。
