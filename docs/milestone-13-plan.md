## 各項目の調査結果と設計

### 1. 保管庫フィルタ(対応拡張子のみ表示・ドット始まり非表示・空フォルダ非表示)

**調査結果**: `core/vault-tree.ts` の `buildVaultTree` は 3 つのフィルタをすべて実装済みで
テストも通っている。`main.ts` の `refreshVault` → `walkDir` → `buildVaultTree` →
`fileTree.setTree` の配線も正しく、`ui/file-tree.ts` は渡されたツリーをそのまま描画するだけ。
静的には原因を特定できなかった。

**実機での観察(ユーザー報告)**: ドット始まり・空フォルダが表示され、ファイルは何も表示されない。

**分析**: この組み合わせは `buildVaultTree` の出力としては起こり得ない
(ファイルが全て除外されるなら、空フォルダフィルタが全フォルダを隠すため
「フォルダだけ見える」状態にはならない)。つまり見えていたものは
`buildVaultTree` の出力ではない可能性が高い。有力な仮説は
**「フォルダを開く」のフォルダ選択ダイアログとの取り違え**
(Windows のフォルダ選択ダイアログはフォルダのみ表示・ドット/空フォルダも出る・
ファイルは出ない — 観察と完全に一致する)。

**方針**: 実機(`npm run tauri dev` + DevTools コンソール)で、フォルダ選択後に
**サイドバー**へ何が描画されるかを確認して切り分ける。バグが実在すれば
`walkDir` の戻り値と `buildVaultTree` の出力をログで比較して原因箇所を特定する。

**結論(実機確認で確定)**: 仮説どおり、観察されていたのは**フォルダ選択ダイアログ**の
表示だった(OS のフォルダ選択ダイアログはフォルダのみ表示する仕様で、フィルタとは無関係)。
サイドバーのフィルタ自体にバグはない。ただし「ダイアログで中身の adoc を確認してから
選べない」こと自体が分かりにくさの原因なので、#9 として UX 改善に再定義する。

### 2. ウィンドウサイズ・位置の保存/復元

公式プラグイン `tauri-plugin-window-state` を導入する。Rust 側の登録だけで
終了時サイズ・位置の保存と起動時復元が自動で効く(JS 側の実装は不要)。

- `src-tauri/Cargo.toml` に `tauri-plugin-window-state = "2"` を追加
- `lib.rs` で `.plugin(tauri_plugin_window_state::Builder::default().build())`
- `capabilities/default.json` にパーミッション追加。識別子は推測せず、
  ビルド後の `gen/schemas/desktop-schema.json` か crate の `permissions/` で実物確認
- `tauri.conf.json` の width/height は初回起動時の既定値として残す

### 3. サイドバー開閉時の比率維持

**原因**: `--editor-ratio` が **workspace 全体幅**に対する `#editor-pane` の width として
使われているため、サイドバー(固定 220px)が開くとプレビュー側だけが縮む。

**設計**: 比率の分母を「workspace − サイドバー幅」(コンテンツ領域)に変える。

- `--editor-ratio` を `50%` から単位なしの割合(`0.5`)に変更
- `#workspace` に `--sidebar-width` 変数を持たせ、`#workspace:has(> #sidebar:not([hidden]))`
  で 220px / 0px を切り替える(純 CSS。WebView2 は `:has()` 対応済み)
- `#editor-pane { width: calc((100% - var(--sidebar-width)) * var(--editor-ratio)); }`
- `ui/divider.ts` のドラッグ計算も同じ分母(コンテンツ領域幅)に合わせる
  (現在の実装はカーソル位置補正だけ行っており分母が workspace 全体のまま)

### 4. ダークモードのテーブル罫線

**現状の答え**: 罫線は UI 全体の `--border`(dark: `#2c2c36`)を共用している。
この色はメニューバー境界やペイン区切りなど「目立たせたくない線」に合わせて
控えめに調整されたもので、テーブル罫線の見やすさは考慮されていない
(意図的なバランス調整ではなく共用による巻き添え)。

**設計**: テーブル専用トークン `--table-border` を導入する。
ライトは現状維持(`var(--border)`)、ダークだけ一段明るく(`#3f3f4c` 前後、実機で微調整)。
`--border` 自体は触らない(UI 全体の枠線が主張しすぎるようになるため)。

### 5. Cargo.toml の改行コード差分

**原因**: リポジトリに `.gitattributes` がなく、`core.autocrlf=true` 環境で
cargo / tauri CLI が Cargo.toml を LF で書き戻すたびに「改行だけの phantom 差分」が出る
(インデックスは LF、内容差分は実質なし)。

**設計**: `.gitattributes` を追加して改行の正規化をリポジトリ側で固定する。

```
* text=auto
```

追加後に `git add --renormalize .` して 1 コミット。
インデックスは既に全ファイル LF なので実内容の変化はない見込み。

### 6. タブ切替時のスクロール位置

**原因**: CodeMirror の `EditorState` にはスクロール位置が含まれないため、
`view.setState()` でタブを切り替えても `scrollDOM.scrollTop` が前のタブのまま残る。
プレビューペインの `scrollTop` も同様。

**設計**: タブごとにスクロール位置を保存・復元する。

- `main.ts` の `switchEditorTo` で、切替前に
  `{ editor: view.scrollDOM.scrollTop, preview: preview.paneEl.scrollTop }` を
  `Map<タブid, …>` に保存し、切替後に復元(未保存のタブ=新規/初表示は 0)
- プレビューは `render` 完了後に復元する(描画で内容が入れ替わるため)
- 保存/復元の対応表そのものに分岐ロジックはほぼないため core への切り出しはしない
  (増えるようなら `core/documents.ts` 側に寄せる)

### 7. プレビュー本文の最大幅

**現状**: `.adoc { max-width: 46rem; margin: 0 auto; }` の固定。
可読性(1行の文字数)を優先した値だが、広いウィンドウでは余白が過剰で
折り返しも早すぎると感じられる。

**設計**: 設定項目「プレビュー本文の幅」を追加する(既定は現状の「標準」)。

- `core/settings.ts` に `previewMaxWidth: "standard" | "wide" | "full"` を追加
  (テストファースト: `settings.test.ts` にフォールバック仕様を先に書く)
- standard = 46rem / wide = 66rem / full = 制限なし
- CSS 変数 `--preview-max-width` 経由で `.adoc` に反映
- 設定ダイアログにセレクトを追加(`getCurrent` プロバイダの流儀に合わせる)
- HTML エクスポートは現状(46rem 相当)のまま変えない(配布物の可読性を優先)

備考: backlog の「図の拡大表示」(46rem に図が縮む問題)はこの設定で部分的に緩和されるが、
ライトボックス等の本対応は引き続き backlog に残す。

### 8. タブのオーバーフロー

現状は `#tabbar-tabs { overflow-x: auto }` で素のスクロールバーが出る。案:

1. **多段タブ**(タブが溢れたら 2 段目に折り返す)
   - 全タブが常に見える反面、段数でエディタ領域の高さが変動する。採用例が少ない
2. **左右送りボタン + タブ一覧ボタン**(サクラエディタ方式)
   - 確実だがボタンが常設 UI を占有する
3. **スクロールバー非表示 + ホイールで横スクロール + アクティブタブの自動追従 + タブ一覧ドロップダウン**
   - VSCode の既定に近い。バーを出さずに 1 段を維持し、
     ホイールで送れる・切替時にアクティブタブが必ず見える・一覧から直接選べる

**決定(ユーザーと擦り合わせ済み)**: 案 3 をベースに、案 2 の**左右送りボタンも追加**する
(ホイールだけでは横送り手段が分かりにくいため)。左右ボタンはタブが溢れているときだけ表示する。

- 実装: `scrollbar-width: none` + `wheel` イベントで `scrollLeft` 加算 +
  アクティブタブの `scrollIntoView` + 左右送りボタン(溢れ検知は ResizeObserver +
  再描画時に判定)+ タブ一覧ボタン(既存の `tabbar-actions` に追加)

### 9. フォルダ選択後に対象ファイルの有無が分かりにくい(#1 の再定義)

**問題**: OS のフォルダ選択ダイアログはフォルダしか表示しないため、
「この中に .adoc があるか」をダイアログの時点で確認できない。
さらに、対応ファイルが 1 つもないフォルダを選ぶと、フィルタが全フォルダを隠すので
サイドバーには**何も表示されず**、「選択が正しく処理されたのか・フォルダを
間違えたのか」がユーザーから判別できない。

**設計**(ダイアログ自体は OS 部品なので変更不可。選択後のフィードバックで補う):

- 対応ファイルが 0 件だった場合、サイドバーのツリー領域に空状態メッセージを表示する
  (例: 「対応ファイル(.adoc / .asciidoc / .asc / .txt)が見つかりません」+
  選んだフォルダ名)。無言の空白をなくすのが主眼
- あわせて、ツリー表示時はサイドバー(またはステータスバー)に対応ファイル数を出す
  (「N ファイル」)。正しいフォルダを選べたことの確認になる
- 件数カウントは `core/vault-tree.ts` に純粋関数 `countFiles(tree)` を追加(テストファースト)。
  空状態の判定は `tree.length === 0` で足りる
- `ui/file-tree.ts` の `setTree` に空状態描画を追加(`.tree-empty` メッセージ)。
  対応拡張子の列挙は core の `SUPPORTED_EXTENSIONS` を export して共有し、二重管理しない
- 余力があれば `open({ directory: true, title: "保管庫にするフォルダを選択" })` で
  ダイアログタイトルにも文言を入れる(Windows での表示のされ方は実機確認)

### 10. 比率が行番号ガター分だけエディタ本文に不利

**問題**: `#editor-pane` の幅にはCodeMirror の行番号ガターが含まれるため、
50% 設定でもエディタの**本文領域**はプレビューよりガター幅ぶん狭く見える。

**設計**: 比率の対象を「ガターを除いた本文領域」に変える。

- `ui/editor.ts` で `.cm-gutters` を ResizeObserver で監視し、実測幅を
  CSS 変数 `--editor-gutter-width` として workspace に反映する
  (ガター幅は行数の桁数・フォントサイズ設定で変動するため静的には決められない)
- `#editor-pane { width: calc((var(--content-width) - var(--editor-gutter-width, 0px)) * var(--editor-ratio) + var(--editor-gutter-width, 0px)); }`
  — 本文領域が (コンテンツ幅 − ガター) × ratio になり、50% でプレビューと本文が同幅になる
- `ui/divider.ts` のドラッグ計算も同じ式の逆算に合わせる
  (分子・分母からガター幅を差し引く)
- 検証: ブラウザプレビューで 50% 時に `.cm-content` 幅 ≒ `#preview-pane` 幅を実測

### 11. Ctrl+F の検索 UI がフォーカス位置で変わる

**現状(実機スクリーンショットで確認)**: エディタにフォーカスがあるときは
CodeMirror(basicSetup 同梱の searchKeymap)の検索パネル(左下・英語 UI・置換付き)、
プレビュー側にフォーカスがあるときは WebView2 ネイティブの検索バー(右上・日本語 UI)が
開き、見た目も機能も異なる。ネイティブ検索は**ページ全体**が対象なので、
エディタ・プレビュー両方のヒットが同時にハイライトされる。

**補足(パネルの正体)**: 下に出る検索バーは CodeMirror 6 標準の検索パネル
(`@codemirror/search`、basicSetup 同梱)。ソーステキスト**全文**が対象で、
仮想化(画面外の行が DOM にない)の影響を受けず、置換・正規表現・
大文字小文字の区別・単語単位マッチまで揃っている。英語 UI で素の見た目なのは
ライブラリ既定のままだから。

**決定(再検討後・ユーザーと擦り合わせ済み)**: 表示モードで使い分ける。
一度「ネイティブ検索バーへの全面統一」に決めたが、エディタ表示中は
置換を含む本格的な検索を使いたいという要件で白紙に戻して再決定した。

- **プレビューのみ表示中**: ネイティブ検索バーのまま(Ctrl+F に手を出さない)。
  プレビュー全文の検索ができ、日本語 UI で違和感もない
- **エディタ表示中(分割・エディタのみ)**: プレビューにフォーカスがあっても
  Ctrl+F で CodeMirror 検索パネルを開く(ソース全文の検索・置換ができる)。
  パネルは日本語化 + Slate スタイルを当てて「素の英語 UI」をやめる

**実装**:

- `ui/shortcuts.ts` の capture フェーズ keydown で Ctrl+F を捕捉し、
  表示モードが preview 以外なら `preventDefault`(ネイティブバー抑止)+
  エディタへフォーカス + `openSearchPanel(view)`。preview のときは素通し
  (表示モードの取得は main.ts から provider を渡す)
- 日本語化: CodeMirror 公式の翻訳機構 `EditorState.phrases` に
  検索パネルの文言("Find" → "検索"、"replace all" → "すべて置換" など)を
  登録する(`ui/editor.ts` の拡張セットに追加)
- スタイル: `.cm-panel.cm-search` 配下の input / button / label を
  Slate トークンで styles.css に定義(設定ダイアログのフォーム部品と揃える)
- パネル UI ごと自作する `search({ createPanel })` は今回は使わない
  (文言 + CSS で不足が出たときの次の一手として温存)

**受け入れたトレードオフ**: エディタ表示中はプレビュー側テキストの検索が
できなくなる(検索はソースに対して行い、必要ならプレビューのみ表示に切り替える)。
