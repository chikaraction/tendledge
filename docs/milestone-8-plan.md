# Milestone 8: サンプル文書の整備とプレビュー品質改善

ユーザーによるサンプル一巡レビューの指摘と、実挙動検証(Asciidoctor.js で実際に
変換して確認)で洗い出した修正候補を統合したマイルストーン。
上位計画は [roadmap.md](roadmap.md)。

## スコープ

### A. プレビューの挙動修正

1. **プレビュー内リンクの制御**(00-index の指摘)
   - 現状: プレビュー内の `link:01-xxx.adoc[]` をクリックすると WebView 自体が
     遷移してしまい、アプリが初期表示に戻る
   - 対応: プレビューペインの `<a>` クリックを常に横取りし、
     - 相対パスの対応拡張子(.adoc 等)→ アクティブ文書のディレクトリ基準で
       解決してタブで開く(パスを持たない無題文書では何もしない)
     - `http(s):` / `mailto:` → システムブラウザ等で開く
       (`opener` プラグインの `openUrl`。`opener:default` に
       `allow-open-url` が含まれることは crate の permissions/default.toml で確認済み。
       ブラウザプレビューでは `window.open` にフォールバック)
     - `#アンカー` → プレビューペイン内スクロール
   - 分類ロジックは `core/preview-links.ts`(純粋関数・テストファースト)、
     パス解決は `core/paths.ts` に `dirname` / `resolvePath` を追加
2. **footnote アイコンの除去**(05 の指摘)
   - `preview.ts` の `decorateFootnotes()` と関連 CSS・アイコン定義を削除

### B. プレビューの CSS / 表示改善

3. **文書タイトル上の余白**(01 の指摘)
   - `.adoc` の padding-top と h1 の margin-top が二重になっている。
     `.adoc > h1:first-child { margin-top: 0 }` で解消
4. **ダークテーマのコード背景**(01 の指摘)
   - インラインコード等の背景 `--bg-subtle` はダークでは地(`--bg`)より
     さらに暗く、判別しにくい。**`--code-bg` トークンを新設**
     (ライト: 従来同等の淡グレー / ダーク: 地より明るい面)し、
     インラインコード・コードブロックに適用。design-direction.md のトークン表にも追記
5. **チェックリストの表示**(02 の指摘)
   - Asciidoctor は ✓(U+2713)/ ❏(U+2751)の文字を出すだけで、
     ❏ には影があり、完了側もチェックボックスに見えない(検証済み)
   - プレビュー後処理で先頭グリフを `<input type="checkbox" disabled>` に
     差し替え、`accent-color: var(--accent)` でテーマ追従
6. **例示ブロック・サイドバーの判別とタイトル**(03 の指摘)
   - 現状どちらもスタイルがなく、ネストしても背景が変わらない
   - exampleblock = 枠線(地は `--bg` のまま)、sidebarblock = `--bg-subtle` 背景、
     と面の作りを変えて、相互にネストしたときに判別できるようにする
   - ブロックタイトル(`.タイトル` → `<div class="title">`)のスタイルを追加。
     例示ブロックの既定キャプション("Example 1." が英語で付く。検証済み)は
     `example-caption` 属性を無効化してタイトル文字列だけを表示する

### C. サンプル文書の記法・説明修正

7. **01**: バッククォート内の `*太字*` 等の記法例が literal 表示にならず
   装飾が効いてしまう(検証済み: `<code><strong>` になる)→
   `` `+*...*+` `` のパススルー付きに修正
8. **03**: 「シンタックスハイライト付きの」という説明は M10 実装まで実挙動と
   食い違うため表現を弱める。例示ブロック・サイドバーにタイトル(`.タイトル`)の例を追加
9. **04**:
   - `| ^OK` は `^` がセル内容として文字表示される誤り(検証済み)→
     配置演算子は `^|` と `|` の前に置く形に修正・説明追記
   - 「基本の表」「セル結合」の1行書き+空行の先頭行が暗黙ヘッダー行になって
     しまう問題(検証済み)→ セルを行分けするか、意図的にヘッダーとして扱う
   - 行結合 `.2+|`・行列同時結合 `2.2+|` の例を追加(節見出しどおりの実体にする)
   - `a|` はセル演算子を `|` の前に付ける記法で、内容は同じ行でも次行以降でも
     書ける(両方有効)ことを説明に補足
10. **05**: 外部 URL 画像は CSP(`img-src` に `https:` なし)により Tauri 実機で
    表示されない → `sample/images/` にローカル画像(自作 SVG)を同梱して
    相対パス参照に変更。CSP は緩めない(XSS 防壁維持)
11. **06**: `{sp}` は単なる半角スペースで「改行させたくない箇所」の説明は誤り
    (検証済み)→ `{nbsp}` の例に差し替え

### D. エディタのハイライト

12. **asciidoc-mode の行結合セル記法対応**: `TABLE_CELL` 正規表現
    `/^(?:\d+(?:\.\d+)?[+*])?.../` は `2+|` `2.2+|` にはマッチするが、
    行のみ結合の `.2+|`(先頭ドット)にマッチしない → パターンを修正

## 実施順序(機能単位で都度コミット)

1. 設計文書(本書)
2. リンク制御(core テストファースト → ui 配線)
3. footnote アイコン除去
4. CSS: タイトル余白 + `--code-bg`
5. チェックリスト表示
6. 例示ブロック・サイドバー(CSS + example-caption)
7. サンプル修正一式 + ローカル画像
8. asciidoc-mode 修正
9. 検証(npm test / build / ブラウザスモーク、Tauri 依存分は verify-tauri)

## 検証方法

- `npm test`(新規: preview-links / paths のスペック)
- `npm run build`(tsc + vite)
- ブラウザプレビューで sample 各ファイルの表示確認
  (リンク遷移抑止・アンカースクロールはブラウザでも確認可)
- Tauri 実機: 相対リンクからのタブオープン、外部リンクのブラウザ起動、
  ローカル画像表示(CSP)— verify-tauri のチェックリストに追記して確認
