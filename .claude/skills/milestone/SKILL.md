# マイルストーン実装ワークフロー

milestone 6(保管庫・タブ・設定画面)で確立した進め方。この型に沿うことで、
テストの抜け・コミットのまとめすぎ・レイヤ違反を防ぐ。

## 手順

1. **設計文書を書く** — `docs/milestone-N-plan.md`。スコープ / モジュール構成 /
   各機能の設計 / 実施順序と分担 / 検証方法。ユーザーと擦り合わせてから実装に入る。
2. **タスク分解** — TaskCreate で機能単位に登録し、依存関係(blockedBy)を張る。
   着手時に in_progress、完了時に completed へ更新する。
3. **core/ にテストファースト** — 新しいロジックはまず `src/core/*.test.ts` に
   日本語の describe/it で仕様を書き、それから実装する(DOM / Tauri import 禁止)。
   既存コードを動かす場合は先に特性化テストで現在の挙動を固定する。
4. **ui/ は薄く** — DOM 接続だけを書く。判断ロジックが現れたら core/ に押し戻す。
   main.ts は配線(合成ルート)のみ。
5. **検証** — `npm test` と `npm run build` を通し、ブラウザプレビューで
   UI をスモークテストする(スクリーンショットよりテキスト系ツール優先)。
   Tauri API に依存する機能はブラウザでは動かないので、`verify-tauri` スキルの
   手順をユーザーに提示する。
6. **機能単位で都度コミット** — 1機能が完成しテストが通った時点でコミットする
   (確認不要・メッセージは日本語)。後からの分割は高コストなのでやらない。

## 分担の指針(トークン効率)

- 設計・横断的リファクタ・レビューは高能力モデル(メインセッション)が担当。
- 独立性が高く仕様が明確な機能(例: 設定画面)は Sonnet サブエージェントに
  委譲してよい。ただし成果物は必ずメイン側でレビューする(過去に実バグを
  1件検出した実績がある)。委譲時はこのスキルの手順 3〜6 を指示に含めること。

## このリポジトリ固有の注意

- Tauri プラグインを増やすときは Cargo.toml + capability の両方。パーミッション
  識別子は crate の `permissions/` で実物確認(推測しない。詳細は CLAUDE.md)。
- プレビューに流れる HTML は必ず `sanitizePreviewHtml` を通す(XSS 防壁)。
- 対応拡張子や設定項目を増やすときは、まず対応するテスト
  (`vault-tree.test.ts` / `settings.test.ts`)に仕様を1ケース足すところから始める。
